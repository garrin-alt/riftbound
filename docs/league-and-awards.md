# Gulf Nexus League (GNL) — How It Works & Awards

This documents two things: how the league itself scores and runs (League Points, Vendettas,
sets/seasons), and the season-long Awards system. Both live entirely inside `index.html` — there is
no backend; everything below is computed client-side from the two Gist files per city.

## How the league works

### Scoring

Every match is worth:

| Result | Points |
|---|---|
| Win | 3 |
| Draw | 1 |
| Loss | 0 |

That's the entire scoring rule (`rvScoreRound`, `WIN_POINTS = 3, DRAW_POINTS = 1`). It's per **match**
(a round, e.g. best-of-3), not per game within the match. There is no separate bonus for winning a
Vendetta grudge match — it scores exactly like any other match. Byes never score.

### GNL: Vendetta — the ladder

**GNL: Vendetta** is the league's actual leaderboard — cumulative **League Points (LP)**, plus each
player's running Match Wins / Draws / Losses and events attended. It's rebuilt from `rivalry.rivalryPoints`
in the Gist and is the only thing that determines standing.

- Ties sort by: total LP → match wins → fewer losses.
- History uploads (backfilling past events into the ledger) **never award LP** and never touch this
  board — only live "Record Results" processing does. Re-uploading history is always safe to repeat
  because of this.
- An organiser can **clear GNL: Vendetta** (resets LP and the event log) without losing any of the
  underlying match history (`h2h`) — the two are stored and cleared independently.

### Vendettas — the narrative layer

Before an event, the organiser can "declare" the night's Vendettas: every attendee is paired with a
rival, generated by `rvComputeVendettas`:

1. For each attendee, rank every *other* attendee they have head-to-head history with, best rivalry
   score first (see "rivalry score" below).
2. Greedily assign pairs, processing players by their strongest available rivalry first, so the two
   best-matched rivals lock in before weaker pairings are made.
3. Anyone left over (no shared history with anyone else attending) is randomly paired with another
   leftover, so **every attendee gets a rival** — random pairs score normally, nobody is penalized
   for the pairing being arbitrary.
4. If an odd player is left with nobody to pair, they're flagged as unmatched for that night.

When results come in, any match that happens to be between declared rivals is recorded as a
"Vendetta settled" — narrative only, tracked separately as a `vendettaWins` counter per player, but
**worth zero extra League Points**. The declared Vendetta list is consumed (cleared) once an event is
processed, so the next event starts clean; an organiser can also clear it manually if a declared
night never happened.

If no Vendetta was declared ahead of time, one can be generated **retroactively** from attendance
after the fact — same algorithm, run against whoever actually showed up.

### Rivalry score

Used only to *rank* candidate rivals when generating Vendettas — not shown as a formal stat. A
weighted blend, normalised against the whole field, of:

- **meetings** (how many times the pair has played) — default weight 70
- **close matches** (games decided by a 1-game margin) — default weight 20
- **swings** (times the series lead changed hands) — default weight 10

Weights are adjustable via sliders in the Rivalry Analyzer UI; `rvComputeVendettas` and the awards
system share the same score so a rebuilt aggregate stays consistent with what generated it.

### Two records of the same matches

- **`rivalry.h2h`** — a flat lifetime aggregate (meetings, wins, close matches, swings, score) per
  pair, with no dates. Fast, but can only answer *"how do these two compare"*.
- **The history ledger** (`riftbound_history.json` / `riftbound_dubai_history.json`) — every match,
  in chronological order, tagged with the Riftbound set and grouped by event. Answers *"when did that
  change"*. Three specific awards (see below) can only be computed from this.

An organiser can **rebuild the lifetime aggregate from the ledger** at any time — this is the safest
way to correct the aggregate, since it derives from the authoritative chronological record rather
than being hand-patched.

### Riftbound sets / seasons

The league runs across Riftbound's own card sets — **Origins → Spiritforged → Unleashed → Vendetta**
(release order). The set list is editable data in the Gist (`hist.sets`), not hard-coded, so a new
Riftbound set doesn't require a site update. Every event in the ledger is tagged with the set it was
played under; the Rivalry Analyzer can slice stats down to a single set.

## Awards

Awards are a **season-long recognition layer**, separate from the ladder:

- They carry **no League Points**.
- They **never appear on GNL: Vendetta**.
- **Every player is eligible**, regardless of rank — each award has its own threshold rather than a
  single global gate, so a newcomer can hold one the first time they qualify.
- They are **recomputed on every render**, not stored as truth — only an organiser's manual
  overrides and hand-written "custom" awards are persisted. This means an award's holder can change
  automatically as new results come in, and there's no staleness to fix.

Most awards are computed from the lifetime aggregate (`rivalry.h2h`). **Two** — Ascension and
The Glorious Executioner — need actual chronology and can only be computed once history has been
uploaded to the ledger; until then they show as locked/pending.

### Giants — the tier every "Giant Slayer" style award measures against

**Giants** are the top quartile (top 25%) by match win rate, among players with **15+ decisive
matches** (`GIANT_MIN = 15`). The bar is self-scaling — it's always "top 25% of the league right now"
rather than a fixed win-rate number frozen in code, so it rises as the league gets more competitive.

### The awards, one by one

| Award | Icon | Category | What it measures | Requirements |
|---|---|---|---|---|
| **Giant Slayer** | 🗡 | Giant-related | Most match wins over Giants, by a non-Giant. Tiebreak: most *different* Giants beaten, then the slayer's own win rate. | — |
| **Mortal Reminder** | 💀 | Giant-related | Biggest win-rate gap in a head-to-head where the *lower-rated* player still owns the series. | Both players 10+ decisive matches, 3+ meetings between them |
| **Mirror Image** | ⚖ | Rivalry | The rivalry that's dead level. Tiebreak: most meetings, then most close matches. | 4+ meetings, match wins tied on both sides, not 0–0 |
| **Dominus** | 🩸 | Rivalry | Never dropped a single *game* to this opponent — perfect game record in the series. | 5+ total games played in the rivalry |
| **Rebuttal** | 🌊 | Rivalry | The rivalry whose series lead has changed hands the most times. Counted exactly from the ledger where available; otherwise counted in upload order (still shown, flagged as approximate). | — |
| **The Hound of a Hundred Bites** | 🐺 | Achievement | Widest circle — most distinct opponents ever faced. | — |
| **The Wandering Caretaker** | 🎖 | Achievement | Most events attended, full stop. "Turning up is its own achievement." | — |
| **Vendetta** | ⛓ | Achievement | Most declared Vendetta grudge matches *won*. | — |
| **Ascension** | ⛈ | Achievement (ledger-only) | Biggest rise in win rate from the first half of a career to the second half. | 4+ events attended; 3+ decisive matches in each half |
| **The Glorious Executioner** | ☠ | Achievement (ledger-only) | Best win rate once Top Cut (playoffs) begins. | 3+ Top Cut matches played |

### Ties

Awards tie constantly (e.g. two players both on nine Giant-slaying wins). Rather than silently
picking a winner by object-key order — which would hand out a title by accident and could quietly
change who holds it whenever the data is re-saved — ties are:

1. Broken deterministically by name (alphabetical) purely to pick a stable "headline" holder for
   display.
2. **Named explicitly** — the winner's detail text says "— shared with X" (or "shared with N others"
   if more than two are tied), so co-holders are never hidden.

### Organiser overrides & custom awards

An organiser can:
- **Hide** any computed award from the public list.
- **Override** a computed award's winner by hand (marked as "set by the organiser").
- **Add entirely custom awards** — their own icon, title, blurb, winner, and detail text — which
  render alongside the computed ones under an `custom` category.

Only these overrides/customs persist in the Gist; every computed award is thrown away and
recalculated fresh on the next render.
